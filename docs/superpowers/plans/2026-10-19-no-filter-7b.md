# No-filter retrieval and 7B diagnostic Implementation Plan

> **For agentic workers:** Use executing-plans in this chat. The user requires native execution; no delegation or additional approval is needed for this authorized local experiment.

**Goal:** Test whether retaining retrieved original evidence without a generative filter improves answers and citations, and compare local 4B and 7B answer models.

**Architecture:** Offline, frozen retrieval reused by both models. Three arms: V3 (vector top 3, 1,800 characters), V6 (vector top 6, 2,400 characters), U (retain V6, append independent graph recall, at most 12 chunks / 2,400 characters). Add whole chunks only, deduplicate, enforce the existing conservative 4,096 request budget. No LLM selection or generated graph facts.

**Tech Stack:** Existing llama.cpp, pinned Qwen3-4B and official Qwen2.5-7B-Instruct Q4_K_M, existing embedding artifacts, Python/pytest.

**Spec:** `docs/design.md`, `docs/contracts.md`, `docs/revisions-and-publication.md`, Task 9 in `docs/superpowers/plans/2026-10-16-domain-kg.md`; user request to remove unreliable filter and test 7B.

## Global constraints

- Offline only; leave production source, approved configuration, stores, image and original frozen evaluations unchanged.
- Exact 7B, rather than substituting 8B; different Qwen generation prevents attributing differences solely to model size.
- Two official shards total 4,683,073,632 bytes, pinned revision bb5d59e06d9551d752d08b292a50eb208b07ab1f; verify both sizes and SHA256 before startup.
- One model at a time, loopback only, CPU 2 threads, GPU 0, one slot. Keep 4B cap 3.5 GB; independent 7B experimental cap 6 GB with 0.25 s RSS watchdog. Never relax the approved 4B runner.
- At most 36 new answer requests / 1,800 s / 4,608 output tokens per model; 120 s per request; halt on two consecutive timeouts or five runtime failures. No optimization after seeing answers in this experiment.
- Use 12 previously unanswered questions from the interrupted 24-question set: u07/u08/u09/u10, three_hop1..4, two_hop1/two_hop3, z1/z3. Labels and retrieval coverage were already inspected; this is a controlled diagnostic, not independent acceptance. Paired questions share chains.
- Same temperature 0, seed 19, 128 output tokens, source-only answer prompt and three-citation limit for both models; raw requests/responses, timings, usage and failures retained privately. Byte-identical within-model requests may be reused with explicit provenance.
- Report semantic answer accuracy over all 12 and citation completeness separately over 10 answerable questions, plus retrieval coverage and refusal behavior. Missing/failed responses remain visible. No best-prefix accuracy claims.
- Prior full-PDF gate (85% answers, 90% citations, dual no worse than vector, complete audit) remains; this diagnostic cannot independently authorize a full-PDF build or mark Task 9 complete.

## Review focus

- Graph additions must never evict any selected V6 evidence.
- Duplicate or unknown chunk IDs fail validation; evidence is original text only.
- Whole-chunk and conservative request limits apply before inference, never silent truncation.
- Both 7B shards must verify before startup; foreign ports/processes remain untouched.
- Runtime failures must be saved before halt, including an incomplete experiment decision.

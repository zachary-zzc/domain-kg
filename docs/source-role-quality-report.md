# 面向准确知识图谱的构建与证据实验（2026-10-21）

本轮找到的可测量改进是：**来源约束下的第二遍原文校正，提高了暂定事实支持率和覆盖率；加入检索上下文的额外收益尚未成立，图检索和关系路径也没有改善这批问题的证据表现。** 因此没有将实验流程默认开启，也没有把模型判断写入已接受事实。

目标承接[检索优化报告](retrieval-quality-report.md)：RAG 与图协助构建准确图谱，并返回足以支持推理的证据。质量判断接受别名、同义表达、原文指代和合理短程推断，不以回答字符串 exact match 计分。字面引文检查只用于证据定位。

## 构图方法

复用已有 6,566 段公开数据及缓存向量，没有新增付费 embedding，没有迁移已接受语料。初始实验选 8 段已知问题材料及 12 段来源留出材料；后者排除此前审阅涉及的 3,155 段，按数据集各取 3 段固定哈希样本。三组留出集的严格结果为：

| 组别 | 有效抽取文档 | 暂定支持事实/审核事实 | 覆盖参考事实 |
| --- | ---: | ---: | ---: |
| baseline（至多 3 条） | 8/12 | 17/23 | 18/77 |
| roles（至多 3 条） | 9/12 | 22/26 | 20/77 |
| coverage（至多 8 条） | 5/12 | 18/23 | 15/77 |

小样本暴露整批校验失败、实体和引文定位问题，不能据此宣称提示词成功。随后另起冻结实验，从尚未作答的 HotpotQA、MuSiQue 各取 8 问，共 16 问及其 228 份上下文。构图不接收问题/答案；来源不全是新的外部材料，这也不是原 6,566 来源的全库检索。

| 组别 | 方法 | 每段上限 |
| --- | --- | ---: |
| baseline | 35B 基础来源约束 | 3 |
| coverage | 35B 关系含义说明与逐句覆盖 | 8 |
| source_repair | 397B 读完整原文，校正并补充 coverage 提案 | 8 |
| context_repair | 同一修正模型/提示，另给 BM25 相关原文及其图提示 | 8 |

397B 在看到候选事实前仅据原文生成独立参考清单。修正看不到清单、问题或答案。相关上下文只帮助解释，端点、引用和限定条件仍须锚定主来源，不能借用别的材料冒充主来源支持。相关材料按数据集隔离，图提示未经语义确认，仅作不可信线索。一份来源上下文为空，两种修正请求相同，复用结果避免重复付费。

扩展实验逐条核验事实协议及来源锚点，保留每条拒绝记录，避免一条错误抹去整段其他提案。这是离线实验能力，**正式批次接受校验没有放宽**。裁判 verdict 从未用于选择检索图边。

## 语义支持与覆盖

原裁判把“期刊由 Elsevier 出版”判为 `created_by` 成立，暴露谓词解释过宽。因此追加了明确标为事后注册的统一盲审：所有 228 来源由 35B 审核，原先固定的 16 来源再由 397B 复核。所有组获得相同谓词定义；不同角色不算同义表达。原始分数保留，不修改候选事实。

补充盲审严格协议成功 156/228 文档。64 份因理由超长或“不支持”事实仍填写参考匹配而失败；离线诊断保留完整理由和 verdict，仅将不支持事实的覆盖贡献归零。缺失/重复 ID、未知字段、未知参考 ID、截断及失败响应仍拒绝。诊断后可比较 **220/228 文档**，其余 8 份单列。下表只是暂定语义结果：

| 组别 | 支持事实/审核事实 | 支持率 | 参考覆盖/1,299 | 覆盖率 |
| --- | ---: | ---: | ---: | ---: |
| baseline | 408/542 | 75.28% | 344/1,299 | 26.48% |
| coverage | 722/959 | 75.29% | 553/1,299 | 42.57% |
| source_repair | 952/1,103 | **86.31%** | 708/1,299 | **54.50%** |
| context_repair | 972/1,130 | 86.02% | 729/1,299 | 56.12% |

228 文档全部提案的协议/来源拒绝数分别为 109/671、305/1,306、163/1,306、206/1,375；上表外未审核有效事实分别为 20、42、40、39 条。27 份独立参考清单未通过原始校验，不进入参考覆盖分母。每份清单最多 8 条，并非穷尽事实集。只看严格成功的 156 文档，四组支持率为 76.07%、76.93%、86.38%、87.08%，方向近似，但存在失败选择偏差。

按文档配对 bootstrap 5,000 次（种子 20261021）：

- 原文修正相对 coverage：支持率 **+11.02 个百分点**，95% 区间 +7.63 至 +14.47；参考覆盖 **+11.93 个百分点**，区间 +8.82 至 +15.10。
- 上下文修正相对原文修正：支持率 **−0.29 个百分点**，区间 −2.50 至 +1.98；参考覆盖 **+1.62 个百分点**，区间 −1.20 至 +4.51。额外收益尚未成立。

区间不涵盖裁判偏差。baseline 与 coverage 容量不同；修正同时增加模型规模和第二遍处理，不能将收益归给单一句提示词或图。固定 16 来源双模型复核 278 条候选，250 条一致（89.93%），28 条分歧。

原文检查确认：修正可删除反向排名边，恢复演员角色/时间与出生日期；但软件兼容性仍可错写为地理 `located_in`，录制年份仍可错写为发行年份，委托/出版仍可错当创作。行政中心不自动意味着行政区包含。Gmina Limanowa 的“不属于”正确保留负极性，展示路径不能丢失它。同名 `plague` 不证明同一场事件。

## 强 RAG、关系检索与路径

使用实际遍历、排序、融合与证据打包实现的离线 I/O 适配器，共用 228 来源池及缓存向量。每题最多 12 段/12,000 字符；PATH 额外至多 2,000 字符，不是完全等 token 比较。图边只据确定性来源校验选入，不用裁判标签。跨材料同名仅为离线检索线索，不声称已验证实体同一性。离线路径保留限定条件，不等于正式接口已支持全部限定条件展示。

**四种构图的 REL 组均与强 RAG 选出了完全相同的原文证据（16/16）。** 两种 PATH 各有 5/16 题增加路径，其余完全相同。参考来源完整覆盖均为 12/16，只作来源命中诊断。完全相同的读者/裁判请求复用响应，避免付费重复和随机波动。没有因路径新增的有证据支持的正确回答。

参考答案可见裁判诊断恢复后报 12/16 证据充分、11/16 读者正确，但它在 York 题中为贴合参考答案忽略必要关系，这些数字不能直接作结论。另加不提供参考答案/参考来源的盲审，15/16 题协议成功，1 题理由超长保持失败：

| 组别 | 有效审核题 | 模型标为证据充分 | 读者有支持且正确 |
| --- | ---: | ---: | ---: |
| 强 RAG / 所有 REL | 15 | 9 | 8 |
| PATH 原文修正 | 15 | 9 | 8 |
| PATH 上下文修正 | 15 | 8 | 8 |

裁判还将“足以拒答”混用为“足以回答”，故 9 不是可靠成功率。原文检查进一步发现：

- Mary 的丈夫是 Frederik，Frederik 是 Queen Margrethe II 和 Prince Henrik 的长子，母亲可合理推断。盲裁判一边说充分、一边输出 insufficient，不能要求原文逐字写出 mother-of。读者答成妻子，属于**证据已有但角色用错**。
- York 段落仅给学校在 North Carolina，未给出生地。原裁判自己补出了出生州，再忽略关系去贴合 1839；正确诊断是出生地这步没有建立。
- IceCat→Firefox→Windows 8 版本支持“该浏览器版本”的通常读法；若要求证明 IceCat 基于恰好那个 Metro 构建则不足。应保留歧义，不将合理表达一律判错。
- 厂牌题缺另一张专辑和厂牌母公司来源，不能把“表演者所属厂牌”偷换成“这张专辑发行厂牌”。添加无关曲目路径后，读者从拒答变成无支持回答。

模型绝对分数不够可靠，但 REL 证据完全相同、PATH 没有新增正确回答、无关路径可能诱发错误是可直接核对的观察。16 题很小，不能推广为图方法普遍无效。

## 正式改动与验证

`extraction_semantics: "source_roles_v1"` 给三种格式加入合法谓词的方向、角色、事件日期、极性和限定条件说明。默认 legacy，旧缓存身份不变，新配置单独标识抽取缓存，embedding 空间不变。提示词不是语义接受门槛。

新增显式 `extraction_response_format: "json_object"` 和 `extraction_enable_thinking: false`。默认保留历史 wire 行为；Object 在系统提示里给同一 schema，严格类型及 canonical 来源/命名空间校验不变，无失败后自动降级。schema 计入上下文预算。见 [provider 配置](providers.md)。

公开合成文本 `Alpha uses Beta. Beta is part of Gamma.` 经真实 ExtractionClient、canonical validator 和 LightRAG 映射：

| 模型 | source_refs_v1 + Object | source_names_v1 + Object | full + Object | names + Schema |
| --- | --- | --- | --- | --- |
| 35B | 通过，3 实体/2 关系 | 通过，3/2 | 响应校验失败 | HTTP 400 |
| 397B | 通过，3 实体/2 关系 | 通过，3/2 | 来源校验失败 | HTTP 400 |

这是连接/协议/映射验证，不是一般领域质量验收；不能说 full 可用，也不能把轻量实验的约 86% 套给正式 KG。正式 general v1 仅 6 个通用谓词，更细作者、表演者、出版者、亲属关系需要版本化 schema。source/context repair、逐条 salvage 和扩展关系表仍属离线实验，没有自动上线。

- 76 项本地回归通过，Ruff 全仓通过，mypy 241 个源文件通过。
- 7 项真实 MongoDB replica set、Neo4j、Qdrant、对象存储回归通过，覆盖旧/新 profile 断点、不完整文档不发布、独立支持、同名隔离及权限边界。本次启动服务已停止，卷保留。
- Task 9 一般语义质量验收不勾选。没有修改 accepted 图、迁移语料、提交或部署。

## 采用的方向

保留正式排序/融合修复和强 RAG 基线，将**原文校正、明确关系 schema、完整证据归属**作为下一阶段候选。上下文应针对缺失角色、指代和关系检索，验证它提供了必要信息再使用；不盲目堆邻居。跨材料身份、缺失中间关系和路径相关性应分别验收，防止名字碰巧相同拼出假证据链。图谱质量提升与最终证据提升是两项独立验收，本轮没有把前者当成后者的证明。

## 模型与对照

回答使用缓存的 Qwen3-4B Q4_K_M：temperature 0、seed 19、关闭 thinking，
4096 上下文，最多 128 个输出 token。两线程 CPU、GPU 0、单槽位。

两组共享 Qwen3-Embedding-0.6B Q8_0 的同一套 1024 维向量，完整覆盖输入，按最多
24 个实际 token 的窗口、UTF-8 字节加权池化并归一化。为遵守现有内存上限而保留
这一方法；它不能代表未分窗、带标准 query 指令或更强 embedding 的最佳向量效果。

| 组别 | 检索方法 |
| --- | --- |
| V 纯向量 | 仅按余弦相似度排序，无 BM25、关键词融合或重排 |
| D 双路径 | 相同向量排序首个种子，加此前固定的原文名称/结构图，贪心扩展两步，向量回填 |

保留此前 `name_graph`、`walk` 和 4B 回答提示词；两组种子统一改为纯向量，以隔离图
扩展的作用。每题最多三个完整片段、1,800 字符，实际最多 1,774 字符。交替组别
调用顺序；新一轮内字节完全相同的请求共享一次真实输出，没有复用旧实验答案。

这不是在正式平台中实现了两个独立发布通路，也不是 LightRAG 完整事实图构建测评。
名称/相邻片段连接是检索线索，不能当作经过语义验证的实体关系。

## 具体失败与边界

- p15：向量 Top-3 含解释“24 小时内运动”的 h14；双路径从 h15 扩展到 h13、h12，
  丢掉 h14，模型因此拒答。贪心路径会替换掉已有的有用向量候选。
- 两段证据的 Cobalt 题：两组其实都召回了必要的 j05、j06。V 拒答，D 答对。
  这是一道问答改善，不能归因于补齐了原本缺失的必要证据。
- 两段证据的 Rho 和 Dales 题：D 答案正确，但分别只引了 j02、j10，漏掉项目/配方
  与设备/原料之间的 j01、j09。检索已完整，提示词仍不能保证引用链完整。
- 四道三段证据题两组均未召回全链。Orion 图路径被同项目的预算片段吸引，Harbor
  被同名快递的日期片段吸引；否定候选的共现也可能产生更强连接。小写 osprey 相关
  片段没有可用名称锚点，D 回退到与 V 相同的结果。
- Linden 三段题，两组均缺少真正的位置原文 j11，却编造了 “Vale Dales”，把供应商
  名称当成所在地。其他三段题主要表现为对可回答问题拒答。

后续开发应另开开发集验证候选保留/融合和引用证据链约束；不能在这 40 题上继续
调优后仍把成绩称为独立新题结果。本轮没有实施这些改动，也没有再次运行模型。

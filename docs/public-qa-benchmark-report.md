按不依赖答案内容的哈希规则选出 22 题，已逐例核对四个模型共 **88 条响应**、原标签与支持 ID。该复核规则在执行期间固定，属于探索性复核；由 Codex 代理完成，不是人工专家金标准审定，未改分。可见有效简称/地点改述被 EM 惩罚、多跳返回中间实体、正确答案漏标准支持、不可答时猜答等情况。DROP 原始多标注中还存在互相矛盾的备选答案；保留该数据噪声并记录，不在看过正式输出后改标签。

## 测试范围与固定指标

本次是**提供相同上下文后的回答、推理、拒答和引用选择测试**。上下文包含作者给定的
证据与干扰段落。它不测全库检索召回，不构建整库 KG，不构成 Task 9 语义抽取验收，
也不触发完整 PDF 构建。没有访问或发送此前 NHS PDF/私有语料。

模型只收到问题与带 ID 的源文本，不收到标准答案、支持事实标签、分解问题或难度标签。
输出协议为 JSON：`answer`、`citations`、`abstain`，最多 8 个合法、不重复的引用 ID。
不可答时答案和引用必须为空。没有 LLM 过滤器、LLM 评分器或逐题重答。

- **严格端到端 EM**：答案按大小写/冠词/标点归一化后匹配作者标准答案或原始别名；
  不可答题必须正确拒答。运行错误、截断、非法引用和输出协议错误计 0。
- **严格端到端 token F1**：对同一合法输出计算答案 token 重叠，保留部分匹配；
  不是人工语义准确率。EM 会惩罚多余解释、未列出的同义表述或人名简称。
- **DROP 本地兼容指标**：数字按数值归一化，保留正负号；多 span 进行最优一一匹配。
  这是独立实现，不声称完全复现官方 DROP scorer；原始输出保留以便重算。
- **完整标准支持覆盖率**：全部 825 道可答题中，输出引用是否覆盖作者列出的全部支持。
  可答题被拒答、输出无效或请求失败均计 0；与答案正确与否分开。
- **引用精确率/召回率**：按作者支持集合统计，额外引用会降低精确率。
  HotpotQA 是句子级，MuSiQue 是段落级，SQuAD/DROP 只有 passage 级。
  混合汇总不等同于逐句证实生成断言，也不证明 DROP 引用了全部计算操作数。
- **拒答准确率**：175 道不可答题单独统计。格式遵循率、HTTP/超时/截断失败、
  已完成比例、调用耗时和已报告用量另列。

每模型始终保留 1,000 道计划分母，不能把中途完成的一小段当成整个测试的准确率。
对未能进入正式测试的模型，保留覆盖率 0，但人读报告中的准确率为“不可用”，
不能把内部用于汇总缺项的 0 分解释为已测得 0% 能力。

## 接口预检与 1.5B 的停止

四个 Qwen 模型均完成 5/5 个合法预检输出。此处只用协议可用性选模型，
不依据预检答案是否正确筛选。

1.5B 原始设置的预检出现 Markdown 包裹、重复输出截断、一次 60 秒超时；
该超时没有 usage，不能按零 token 统计。其两次有 usage 的请求分别报告输出
539 和 1,283 token，均超过请求的 `max_tokens=512`，因此不能声称已验证输出预算。

随后只对一题被排除的短预检题做了 5 次有限接口适配，完整保留每次请求和响应：

1. user-only 提示、温度 0.6、2,048 token：非空答案却标记拒答，并有 Markdown 包裹。
2. 加 JSON object 模式：content 为空。
3. 简化格式示例：缺少 `abstain` 字段。
4. 强化字段约束、温度 0.7：仍有 Markdown 包裹且没有引用。
5. 强化 JSON 首尾约束、4,096 token：答案和引用可读且正确，仍包裹 Markdown。

去系统提示与温度选择依据
[DeepSeek 官方使用建议](https://huggingface.co/deepseek-ai/DeepSeek-R1-Distill-Qwen-1.5B)。
五次均未通过本次预先固定的严格协议，因此遵守用户的五次失败上限，停止继续适配。

最后一题仅需确定性移除代码块即可解析，提示后续“容错适配器”是可单独验证的方向；

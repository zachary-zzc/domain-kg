# 正式检索排序、融合与离线证据验证

2026-10-21。目标是让 RAG 与图共同提供准确、可追溯的知识证据，不以答案字符串匹配优化系统。

**结论：正式链路已修复缺少相关性的图排序、重复图投票和破坏证据的装入方式；离线结果消除了融合退化，但尚未证明图能稳定优于强 RAG。** 关系约束只在 35B 图的未回答队列补齐了 2 道参考证据，其中 1 道问题本身仍有歧义。图关系的语义准确性、关键关系覆盖和问题角色约束，仍是需要继续解决的问题。

本次没有新调用构图、嵌入、回答或评审模型，也没有启动本地模型。使用保存的 6,566 段材料、1,000 道问题、五组构图输出和原始向量；14,839 个历史调用文件的哈希在重放前后保持一致。没有修改既有语料、人工修订记录或已发布知识图谱。

## 已修改的正式行为

1. **种子与图排序。** 问题中的可见实体名称、别名、标识符可以匹配种子，避免要求整句问题出现在实体名中。保留向量种子的原顺序。图候选按当前可见来源的 BM25、关系提示和支持路径排序，再取前 50；UUID 只作同分稳定排序。
2. **融合。** 向量与词法仍用常数 60 的 RRF。图重复找到已有文本候选时增加经过校验的关系信息，不再无条件增加第三票。图独有来源仍可按图名次与文本尾部竞争，没有强制图配额。独立 graph 模式仍按图排名返回。
3. **证据装入。** 优先保留完整段落，去重、跳过放不下的候选并从后续候选补位。预算允许时保留各 KG 的完整证据；只能返回摘录时明确标记截断并清除其图路径。
4. **路径与边界。** 路径保留实际谓词、方向、否定或不确定极性，返回前与封存支持记录核对。超出词项预算返回领域错误。权限、KG 命名空间、逐步可见支持、接受版本和返回前重校验继续生效。

这些修改不把图边变成已证实的事实。`verified` 仍表示来源跨度与 schema 经过校验，不等于关系在语义上一定正确。Fast 仍不调用生成式查询模型或重排模型。

## 统一比较方式

离线适配器复用正式的 BM25、种子排序、`GraphRepository.traverse`、路径构造、图排序、融合与装入函数。保存的公共数据代替数据库 I/O 和身份认证；真实服务的权限与发布正确性另外通过真实存储验证。离线相同名称的连接只是按数据集隔离的实体提示，不能当作正式实体合并。

离线按保存段落建立 chunk，并统一附上标题；向量相似度在本地精确重算。它没有重新执行正式摄取/切块、Qdrant ANN 或 LightRAG native mix，也没有伪造接受发布清单。复用核心算法消除了旧基准另写一套排序的偏差，但仍不是整个在线服务的端到端质量测试。

| 方案 | 实际行为 |
| --- | --- |
| V12 | 保存向量的前 12 段，使用同一装入函数 |
| RAG | 向量前 50 + BM25 前 50，RRF 后装入 |
| GUIDED | RAG + 正式链路的关系提示排序与保守图融合 |
| REL | 在同一个有界图中，要求问题实体锚点及匹配的末端谓词，再使用相同保守融合 |
| PATH | REL 的完全相同来源，额外展示引用齐全的关系路径 |

REL 是单独的离线实验：使用有限词法规则识别关系；没有实体锚点或关系提示时弃用图补充。它从问题锚点重新追踪路径，避免向量种子中的中间节点把解释链压成一跳。它**不是完整的关系语义查询器，也没有替换正式服务默认策略**。正式服务已有的 `SearchFilters.predicates` 则仍是所有分支共同遵守的硬过滤条件。

各方案最多 12 段、12,000 个来源正文字符，候选池每分支 50，图上限两跳、200 节点、400 边。PATH 额外允许 2,000 个路径 JSON 字符，只展示各边原文都在已选来源中的路径；因此它不构成总 token 预算完全相同的回答实验。

保存向量重新计算后，1,000 道题的前 12 排名全部复现。RAG/V12 在五组构图模型间必须完全一致。最终生成 25,000 条记录，并验证所有预算以及 REL/PATH 来源一致性。

## 指标与分母

沿用此前确定的 **205 道共同复核题**，便于对照；另列 **584 道未生成过回答的问题**，其中原参考可答 470 道。其他 211 道保留逐条记录，不混入主表。未回答队列尚未完成题目质量筛选。

自动指标是“参考支持证据全部出现在所选完整来源中的比例”。它只用于诊断召回，不是答案准确率、事实正确率或答案 exact match。等价来源可能不在原参考里，参考本身也可能遗漏关系。部分来源被截断不能冒充完整证据。

原有 8,299 条回答没有改写，也不能替新上下文评答案。下面不报告新的答案正确率。

| qwen3.5-397b-a17b | 79.51% | 82.44% | 82.44% | 74.89% |
| qwen3.5-122b-a10b | 72.68% | 82.44% | 82.44% | 74.89% |

| deepseek-r1-distill-qwen-1.5b | 82.44% | 82.44% | 82.44% | 74.89% |

第一列来自保留的 v2 负结果，已使用新排序和装入，只有融合仍是重复图命中可额外加票的三路 RRF；它不是未经修改的整套旧正式服务成绩。最终 GUIDED 在未回答队列均为 74.89%。主队列各模型相对 RAG 的参考完整改善/退化均为 0/0，平均参考支持召回也同为 91.63%。

35B 的两个参考证据改善均发生在未回答队列，已逐项阅读：

- **Cock and Bull 作者出生年份**：新增 Will Self 的出生来源，与作品作者来源形成一致证据链，支持 1961。接受 Will Self 与 William Woodard Self 的上下文对应，不要求名字完全一致。这是明确的证据补齐案例。
- **Helvetia 同县城市的最湿年份**：新增 Pima County 范围包括 Tucson 的来源，补上参考链。但同县可能有多个城市，问题没有唯一指定 Tucson，因此不能直接升级为唯一答案正确。

保守融合不会无条件提升已在文本候选池中的图命中，这能防止噪声挤掉文本证据，也可能限制真正有用的桥接来源晋升。当前结果只能说明这组策略下的表现，不能证明图没有价值。

有界扩展也仍有明显限制：27B 主队列 175/205 道触及图裁剪；26 道产出约束候选，23 道有来源齐全的可展示路径。REL 仅有 2 道改变了最终来源集合。候选池和路径覆盖不足、保守融合及构图缺失共同限制了本次结果，不能把零净增益只归因于模型大小。

## 语义复核，不使用答案 exact match

原生助手按来源内容进行复核，没有额外评审 API；这些是有理由的开发审查，**不是独立专家审查或正式人工策展记录**。

固定样本在查看结果前按题目 ID 的 SHA-256 选定：每数据集 3 题，共 12 题，使用 27B 图。RAG 与 REL 均为：

| 证据充分性 | 数量 | 判断方式 |
| --- | ---: | --- |
| 足够 | 9 | 可从所选来源支持所问内容，接受别名、合理改写和有依据的推断 |
| 部分 | 2 | 有相关来源，但缺关键桥接关系 |
| 不确定 | 1 | 有合理解释，但还需实质地理证据 |

例如，“Tom 是 Henry 的儿子且为 Edward 的同父同母兄弟”，结合另一段 Henry 的父亲信息，可以支持 Edward 祖父的回答；“Czechoslovak crown 是一种货币”可由汇率和货币上下文判断，不必出现定义式原句。

相反，主演与电影已经找到，但演员来自哪里没有找到，仍是缺一跳。Vivaldi 那道题的原参考还把歌剧演出地当成出生地依据；扬州/姜堰的沿海属性也需要地理关系进一步确认。本次保持 205 题分母不变并明确标注，既不静默改金标，也不为了计分放宽事实条件。

这 12 题中 11 题没有可展示的约束路径；剩余一题返回“Elizabeth II 参加官方庆典”。该边忠于原文，却不回答“哪位演员饰演 Elizabeth II”：`played` 匹配 `participated_in` 没有解决人物角色。证据充分与路径有用必须分别判断。

另从 27B 全部 106 道具有可展示路径的题中，按 SHA-256 顺序取 6 道进行路径审查。其中 1 道与上述 12 题重合，不能当成独立样本相加。6 条均为单跳，其关系可由完整来源支持；4 条只覆盖问题的一部分，2 条没有约束到所问目标，没有一条单独构成完整问题的推理链。该样本以“存在路径”为条件，不能估计全体精度。

## 构图问题不能靠重排掩盖

另对每模型按哈希取 4 条保存事实，共 20 条记录、17 条不同事实进行来源语义审查：16 条有支持、1 条角色不明确、1 条无有效信息、2 条不受支持。样本很小，不能作为模型精度排名。

- 游戏原文 `developed by Bits Studios` 与游戏 `created_by Bits Studios` 一致；Academy Awards 与 Oscars 可以视为同义。
- “Miki Howard 是歌曲艺人/演唱者”不足以确立她是词曲作者，宽泛的 `created_by` 不能直接用于作者问题。
- 把作品与 Gershwin 的作曲关系记成作品 `uses` 人物，或把 Patti Page 唱片另一面的歌错误归给同段中的 Joni James，都是实质关系错误。
- 额外错误诊断还看到“入籍日期 → 出生日期”和“作者 → created_by → 作品”的反向断言。它们有原文引用，但引用存在不能证明关系正确。这些案例不是上述随机样本的额外统计分母。

因此，下一阶段应围绕 **关系角色与方向、实体对应、否定/时间限定、关键桥接关系覆盖** 建立构图验收。RAG 可以找到完整上下文，图可以组织关系和证据，但不能把同段共现、泛化谓词或名称相同直接升级成确定知识。对已有离线事实可以继续做类型/方向检查和带来源的错误归类；涉及重新抽取或正式策展的改动应保留修订与来源归属。

## 验证与复现

离线主命令（输出目录必须不存在，防止覆盖旧结果）：

```bash
OPENBLAS_NUM_THREADS=1 OMP_NUM_THREADS=1 PYTHONPATH=src:. \
  .venv/bin/python -m eval.scoped_retrieval_run \
  --output .cache/scoped-retrieval-2026-10-21-v5
```

运行时禁用 socket 连接，没有网络回退。固定输入、实现与历史调用记录均存哈希。V12、RAG 与图方案在相同协议内比较；本协议改变了候选池和正文装入，不能把数字直接套到旧 U12 回答上。

本轮检查通过 **536 项非存储回归、84 项任务检查（其中 47 项标记为 storage）、另行重跑的 7 项融合集成检查及 1 项最终可选重排检查**。这些计数有重叠，不相加当作独立用例数量。`ruff check .` 与 `mypy src`（240 个源文件）通过；没有把控制台浏览器或完整 release gate 算进本次验证。

真实 MongoDB replica-set / Neo4j / Qdrant / S3 测试使用固定模拟 provider，验证权限、隐藏节点与别名、引用路径篡改、发布失败、并发版本和删除恢复。没有把公共数据适配器当作权限验证。可选重排的额外失败用例保证它仍能提升图独有来源，而不会被重复图投票抑制规则误伤；离线比较始终关闭重排。

独立进程 v4 重放的汇总、逐题结果、向量排名和语义审查材料逐字节一致。最终版本另写 v5 清单，以记录最后的可选重排修复：其逐题结果、向量排名、语义审查输入与两个 v4 进程完全相同，模型汇总也一致；实现哈希更新为最终代码。最终检查和输出一致性记录于 [verification.json](../.cache/scoped-retrieval-2026-10-21-v5/verification.json)。本次启动的四个存储服务已停止，数据卷保留。

存储测试复用了 `scripts/smoke.py` 的任务 11–13 清单、初始化函数与笔记本资源检查，再补发布/并发/删除用例。离线依赖缓存缺少 smoke 默认同步所需的构建包，因此使用已安装环境执行等价 pytest 清单，没有安装或下载依赖。Qdrant 恢复既有集合时曾早于 HTTP 就绪报告 healthy；等待本地端点就绪后重新运行。

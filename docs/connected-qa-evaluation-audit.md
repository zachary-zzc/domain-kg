# 评估审计：语料规模、问题来源、建图与检索评分

审计日期：2026-11-01。范围是 `connected-qa-2026-11-01` 的 100 题比较及后续去路径消融。仅检查既有数据、程序和原始响应，没有新增模型调用、修改生产算法或覆盖历史分数。

**审计结论：数据来源、实际输入一致性和“指定参考证据覆盖”的计算通过核查；整套评估尚不足以验收知识库的语义质量或证明新旧算法优劣。** 尤其不能把下载的 219.60 MB 题库说成本次知识库大小，也不能把答案字面 EM/F1 或未经校准的单模型审查当作真实正确率。

## 1. 三种规模必须分开

### 下载的原始题库文件

下表是本机实际保存且已逐文件重验字节数和 SHA-256 的数据，不是各项目全部训练/开发/隐藏测试 split 的总量。MB 按 1,000,000 字节计算。

| 数据集 | 本地文件范围 | 问题/变体记录数 | 未压缩文件 bytes | MB |
| --- | --- | ---: | ---: | ---: |
| SQuAD 2.0 | train + dev | 142,192 | 46,494,161 | 46.494 |
| HotpotQA | dev distractor，Parquet 转 JSON | 7,405 | 45,931,342 | 45.931 |
| MuSiQue-Full | dev | 4,834 | 59,422,562 | 59.423 |
| DROP | train + dev | 86,945 | 67,756,820 | 67.757 |
| 合计 | 六个 JSON/JSONL 文件 | 241,376 | 219,604,885 | 219.605 |

记录数不是相互独立的问题数：MuSiQue-Full 的 4,834 条包含 2,417 组可答/不可答变体；其他数据集有多个问题共用同一段落。题库文件还包含问题、答案、支持标签、元数据及多次重复的上下文。

原始上下文的进一步核查：SQuAD train/dev 分别有 19,035/1,204 个段落记录；DROP 有 5,565/582 个段落记录。Hotpot dev 共出现 73,700 个上下文段落，按正文精确去重为 66,609 个；MuSiQue-Full dev 共出现 96,626 个，按正文精确去重为 26,326 个。此类“正文去重”也不是语义去重或实体消歧。

### 本次真正参与建图与检索的内容

本次只从既有 1,000 题样本中，每个数据集按固定哈希顺序选 25 题，取这些题附带的证据和干扰段落。它们合成一个检索池；并非分别构建四套完整知识库。

| 来源 | 测试题数 | 段落记录数 | 标题+换行+正文的 UTF-8 bytes | 十进制 KB | 抽取窗口数 |
| --- | ---: | ---: | ---: | ---: | ---: |
| SQuAD 2.0 | 25 | 24 | 20,644 | 20.644 | 25 |
| HotpotQA | 25 | 242 | 137,182 | 137.182 | 244 |
| MuSiQue-Full | 25 | 458 | 225,199 | 225.199 | 460 |
| DROP | 25 | 23 | 22,436 | 22.436 | 25 |
| 合计 | **100** | **747** | **405,461** | **405.461** | **754** |

这相当于 **0.405 MB / 0.387 MiB** 文本，404,400 个 Unicode 字符，按空白切分约 66,493 个词。747 个文档 ID 实际表示短段落，最大仅 2,084 字符，不是 747 篇完整文章。

保存的 `corpus.json` 为 1,072,037 bytes（1.072 MB），因同时保存正文、支持单元和元数据而比原文大。未测量 Neo4j/Qdrant 的数据库磁盘占用；模型请求日志及 JSON 缓存的大小也不能当知识库大小。

此前另一次 1,000 题实验使用 6,566 个段落、3,517,255 bytes 原文（3.517 MB），也不是 219.60 MB 全量知识库。这两个历史实验不可混为一谈。

### 数据集本身不等于知识库

四者主要是“问题 + 上下文 + 答案/支持标注”的 QA 数据集，不是带标准节点和关系的 KG。HotpotQA 另有真正的 fullwiki 检索资源：官方简介段落归档为 **1,553,565,403 bytes 压缩文件**；本次没有下载或索引该资源。[官方语料说明](https://hotpotqa.github.io/wiki-readme.html)

## 2. 问题和标准答案从哪里来

| 数据集 | 作者如何构造问题 | 本次的适用性 |
| --- | --- | --- |
| [SQuAD 2.0](https://rajpurkar.github.io/SQuAD-explorer/) | 众包人员根据维基百科段落提问并标答案片段；另写看似合理但段落无法回答的问题 | 适合段落事实定位和拒答。很多问题依赖原上下文，直接改成全库检索会产生歧义 |
| [HotpotQA](https://arxiv.org/abs/1809.09600) | 作者筛选有联系或可比较的文章对；众包人员撰写跨文档问题并标支持句 | 与多步检索最相关。当前只用 distractor 开发集中的小样本，不是完整 fullwiki 测试 |
| [MuSiQue](https://aclanthology.org/2022.tacl-1.31/) | 组合相互依赖的单跳问题，过滤可绕过中间步骤的题；Full 添加缺失证据的不可答对照 | 适合检验中间证据链；汇总不同问题的上下文后，必须重新核查不可答标签 |
| [DROP](https://aclanthology.org/N19-1246/) | 众包人员围绕段落撰写需要计数、排序、加减等离散推理的问题 | 适合测阅读与计算。不是专门的跨文档图检索测试，不能要求增加边就必然提高它的分数 |

本轮已把 **100/100** 条问题、标准答案、支持标注和段落重新追溯到本机原始作者数据，通过原有格式转换重建，结果与冻结样本完全一致。阿里模型负责抽取和回答，没有生成这 100 道题或其标准答案。

样本选择顺序也重放一致：作者 dev → 既有分层 1,000 题 → 各数据集按哈希取 25 题。相同问题没有因本轮模型回答好坏被选择或删去。但这套题已经被前序实验使用，不是未见过的最终留出测试集；每组仅 25 题，也不代表作者数据集原始分布。

公共英文短段落可用于通用功能诊断，不能替代中文激素资料的表格、价格、单位、采样时间和条件、版本冲突测试。当前语料的规模、领域和结构都不足以支持大规模领域知识库结论。

## 3. 实验实际做了什么

1. 冻结相同 747 个段落和 754 个窗口；不把问题、答案或支持标签送入抽取器。
2. 用阿里 `qwen3.6-35b-a3b` 分别执行旧/新抽取器。全文相同、模型与主要调用参数相同；词表、抽取提示和校验行为是算法比较的一部分。
3. 使用既有 Alibaba `text-embedding-v4` 向量缓存，以及生产 BM25、图遍历、排序和融合代码的离线适配器。比较 fast、旧图和新图三组。
4. 每组最多 12 个原文段落、14,000 字符；图路径还受评测适配器 2,000 字符约束。随后由同一阿里 35B 模型回答，再计算指定证据覆盖和字面答案分数。
5. 补充使用阿里 397B 作语义审查，但该审查有协议错误且未充分校准。后续另有 100 题去路径控制实验，其中 88 个请求复用历史响应、12 个新调用。

这不是完整线上服务端到端测试：未把材料作为正式 KG 发布到 MongoDB/Neo4j/Qdrant；使用按数据集隔离的名称归并提示，而非验证过的生产实体解析。某文档任一窗口失败时，该文档不提供图事实，但所有组保留相同全文，便于隔离图的增量贡献。

计时排除了数据库 I/O、缓存向量排名的计算等阶段。因此此前毫秒数是检索核心的离线耗时，不能据此报告线上吞吐或全库检索延迟。

## 4. 节点、关系和“有效性”统计到了哪一层

本轮重新统计了实际离线图，并区分窗口观察记录与名称归并后的节点：

| 指标 | 旧图 | 新图 |
| --- | ---: | ---: |
| 节点观察记录，跨窗口可重复 | 5,835 | 4,460 |
| 离线按名称归并后的节点 | 5,002 | 3,543 |
| 上述离线图的孤立节点 | 1,415 | 0 |
| 关系观察记录 | 3,372 | 4,382 |
| 文档内端点/谓词/极性/限定字段完全相同的记录去重后 | 3,369 | 4,217 |
| 至少含一条关系的文档 | 633/747 | 559/747 |
| 无向连通分量数，含孤立节点 | 1,897 | 378 |
| 最大分量节点数 | 390 | 554 |
| 悬空边，端点不存在 | 0 | 0 |

名称归并只是离线检索提示，不能称为经过实体消歧的真实唯一实体数。关系去重也只是字段去重，不等同于语义去重。

已有校验覆盖结构、类型约束、端点引用、原文引句和作用域等。**引句确实存在，不保证从引句抽出的关系含义正确。** 目前没有系统测出以下指标：

- 节点是否是有用、边界正确的实体，同名节点是否错误合并。
- 关系是否由原文支持，方向、否定、时间、条件、单位是否保真，即事实精确率。
- 原文应抽出的重要事实漏了多少，即事实召回率。
- 同义谓词是否一致、跨文档桥接是否正确。

四个 QA 数据集不提供完整 KG 金标准，因此不能直接据其答案算节点/边的精确率和召回率。需要另建原文事实审查集。此前激素语料只有少量关系抽查，也不能代替系统估计。

零孤立节点是当前算法通过删孤立观察实现的不变量，不是独立的质量证明；更大的连通分量也可能来自错误合并。尤其新图虽然边更多，有关系的文档却减少，因此单看边总数不充分。

## 5. 检索是不是要求每个字匹配

需要区分四个不同步骤：

| 步骤 | 当前实际规则 | 是否要求字面一致 |
| --- | --- | --- |
| 检索候选生成 | 向量语义相似度 + BM25 + 图关系 | 不要求问题与段落逐字相同 |
| 指定证据覆盖评分 | 检查返回来源是否包含作者指定的支持单元 | 匹配支持 ID；另检查该原文单元未被截断 |
| 答案 EM/F1 | 规范化后比较标准答案字符串，或计算词元重叠 | EM 有字面约束；F1 仍不是语义判断 |
| 建图出处校验 | 生成的名称/引句必须能定位回原文 | 有字面出处约束，是建图验证，不是检索评分 |

`evidence_coverage` 中确实有 `unit['text'] in item.text`，但这是检查所引用支持文本是否完整出现在返回原文里，不是在比较问题和答案。本轮对全部 **300 个检索结果包** 重算：

- 返回内容均是完整原文，没有截断。
- 没有支持单元因该字面检查被额外排除。
- 去掉此检查、仅按原文支持 ID 计分，结果完全相同。

因此，本次 79.0% 完整支持覆盖不是“个别字不匹配”造成的。它有另一种严格性：必须覆盖作者列出的全部支持，而其他语义等价、同样充分的证据不会自动计入。这个指标只能叫 **指定参考证据覆盖**，不能直接叫“实际检索正确率”。

本轮补算不同深度，分母均为 81 道原标可答题。三组在这些参考指标上完全相同：

| 返回前 k 个段落 | 至少命中一个标准支持 | 平均标准支持召回 | 全部标准支持齐全 |
| --- | ---: | ---: | ---: |
| 1 | 75.3% | 53.3% | 33.3% |
| 3 | 93.8% | 80.0% | 66.7% |
| 5 | 96.3% | 85.1% | 71.6% |
| 10 | 98.8% | 88.6% | 76.5% |
| 12 | **98.8%（80/81）** | **89.8%** | **79.0%（64/81）** |

前 12 段完整覆盖按来源分开为：SQuAD 11/11、HotpotQA 22/25、MuSiQue 7/20、DROP 24/25。MuSiQue 全部 20 题都至少找到一个支持，主要难点在是否补齐其余证据。

也补算了参考文档 MRR=0.850、nDCG@12=0.809。只按标注支持文档计算的 precision@12 为 12.45%，但**不能解释为 87.55% 文档无关**：标注并非全库相关性穷举。没有完整相关性/替代证据标注时，precision、nDCG 都只能按参考集合解释。

## 6. 评估目前的实质缺口

### 答案格式与字面评分不完全适配

回答协议允许字符串或多个字符串，但非 DROP 任务也套用了多片段一一匹配规则；这是本地指标，不是四个数据集官方脚本的完整复现。例如：

| 生成答案 / 标准答案 | 当前 EM | 当前 F1 |
| --- | ---: | ---: |
| `The Ethiopian Empire is older.` / `Ethiopian Empire` | 0 | 0.667 |
| `five games` / `five` | 0 | 0.667 |
| 两段 `immunoglobulins`、`T cell receptors` / 一段 `immunoglobulins and T cell receptors` | 0 | 0.375 |
| 两段 `Russians`、`Russian forces` / `Russians` | 0 | 0.500 |

最后两例展示了答案分段对本地分数的影响。第三例在真实题目还有其他标准别名，因此该题最终取最大值后可能不同；表中是明确指定这一对表达的评分，不冒充整题重算结果。

另一方面，答案猜中也会得分，即使证据缺失。fast 有 2 个可答题 EM=1 但未覆盖全部标准支持；这不自动说明两题都错误，但已复核的作者出生年份例子确实缺所需出生信息。

因此 EM/F1 保留为兼容和诊断指标，不能担任唯一 QA 质量指标。需要分别报告事实答案正确、当前证据是否支持、引用是否准确及拒答是否适当。

### 原任务被改成公共检索池，标签适用范围改变

SQuAD/DROP 的问题经常针对特定段落，可能省略人物或事件。MuSiQue-Full 的“不可答”依赖某段缺失；混合语料后该标签不能直接继承。本轮检查 5 道 MuSiQue 不可答题，没有发现其可答版本的完整原始支持集合重新出现在池内，但这不排除其他语义替代证据，也不能验证 14 道 SQuAD 不可答题在新检索范围内仍不可答。

已冻结的原标签不能在看过模型答案后悄悄改写。应保留历史分数，将“原任务评分”和“公共池重新审定的可答性”分为不同版本。

### 语义评审未达到可信主指标要求

阿里 397B 的评审提示明确允许同义表达、日期/算术等合理推理，并不要求逐字复现答案。但单模型判断没有充分校准：

- 原审查有 fast/旧图/新图分别 1/6/14 条协议失败。
- 另发现 fast 9 条、新图 1 条在已有拒答响应时标记 `no_reader`；其中 fast 1 条根本没输出 `reader_status`，被代码默认填成 `no_reader`。这会混淆“没有回答记录”和“明确拒答”。
- 存在把 `counsel`/`council` 的明显拼写差异过度严格解释的个案。
- 评审同时看到标准答案和模型回答，可能受到锚定；“语义评审”不能仅靠换成更大的模型就视为可靠。

这些问题不改变参考召回或字面 EM 的数值，但使语义质量和拒答结论不宜成为算法验收依据。相关异常全部另存，未把缺失判断自动补成正确或错误。

### 路径适配器与完整系统测试不同

生产检索核心被复用，但传给回答模型的路径由离线适配器选择，存在整段引文重复和 2,000 字符预算限制。去路径消融说明在该提示与打包方式下分数恢复，不能直接推出所有生产客户端使用图路径都更差。

## 7. 在继续优化前，评估应如何修正

1. **保留两条独立评测轨道。** 作者原任务按原上下文和官方指标测试阅读/推理；公共池检索只使用在该范围内问题明确、可答性已核验的题。不可答题单独验证，不沿用局部上下文标签。
2. **检索指标拆开。** 保留可复现的参考 Recall@k、CompleteSupport@k；增加语义证据充分性，接受任意同样有效的证据路径。单独统计排序、无关上下文和证据缺口，不用字符串答案衡量检索。
3. **回答指标拆开。** 固定输出协议并与各数据集官方 scorer 对齐；协议失败与内容错误分开。事实正确性、证据支持、引用及拒答分别判定，不能把 EM 改名为准确率。
4. **先校准评审器。** 用预先确定的等义改写、别名、合理短推理、等值单位、缺中间证据、错误数字、否定反转和正确拒答对照；缺字段或状态矛盾必须标为未判定。争议例由独立复核裁决，且与生成答案隔离评估证据充分性。
5. **补建图语义审查。** 在抽取前冻结代表性原文和应提取事实；分别审查事实精确率、重要事实召回、限定条件和实体合并。按文件类型、普通文档/汇总文档分层，不靠节点数或零孤立率验收。
6. **区分开发集和最终留出集。** 当前 100 题只用于开发诊断。后续应使用未参与调试的题，并纳入用户中文激素资料；另用更大、明确标注原文 bytes 的语料测规模和线上延迟。

这些是后续验收条件，不表示本轮已经完成了专家标注、评审器校准或更大规模测试。当前可保留的结论是：**在这个 0.405 MB 抽样库及指定参考证据口径下，新图没有增加标准支持覆盖；尚不能据此认定实际语义检索或整体 QA 更差。**

## 8. 本轮完成的核查

- 六个原始文件的 byte 数和 SHA-256 一致。

- 300/300 个检索包的参考覆盖重算一致；字面原文完整性检查没有导致额外漏计。
- 300 个回答的 EM/F1 重算一致；没有修改历史标签或分数。
- 节点/关系、孤立节点、连通分量、悬空边和有关系文档比例重新统计。
- 现有数据转换、评分、离线检索及语义评审边界测试：**20 passed**。测试通过只证明已覆盖的程序行为，不代表上述方法学缺口不存在。

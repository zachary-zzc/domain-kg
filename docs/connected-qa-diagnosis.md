# 开放关系抽取后的检索与问答：原因诊断

2026-11-01。针对 [首次比较报告](connected-qa-benchmark-report.md) 补充离线重放、逐题复核和阿里 API 控制实验。

**结论：结构目标已实现，但建图、检索和回答没有形成有效配合。** 新旧图之间的答案分差很小，且混有格式扣分；真正需要修复的是抽取协议失败、重要中间证据没有入选、无关路径进入回答上下文。没有证据说明必须恢复固定关系词表或保留孤立节点。

本轮未修改生产算法、配置、原标签或正式比较结果，也没有发布或迁移任何 KG。

## 这些数据集测什么

| 数据集 | 原始任务 | 本次样本 | 对本项目的用途与限制 |
| --- | --- | --- | --- |
| [SQuAD 2.0](https://rajpurkar.github.io/SQuAD-explorer/) | 给定英文维基百科段落，抽取答案；部分问题故意无法从段落作答 | 25 题：11 可答、14 不可答 | 检查定位事实和拒答。原任务通常不是全库检索；有些问题依赖上下文省略主语 |
| [HotpotQA](https://hotpotqa.github.io/) | 跨多个英文维基百科段落回答，多为桥接或比较，带支持句标注 | 25 题：17 桥接、8 比较 | 检查能否找到并组合中间事实 |
| [MuSiQue-Full](https://github.com/StonyBrookNLP/musique) | 组合 2–4 跳问题，包含缺失关键段落的不可答版本 | 25 题：6 个两跳、10 个三跳、4 个四跳、5 个不可答 | 对完整证据链要求较高；不应仅凭终点答案评价推理是否有依据 |
| [DROP](https://github.com/allenai/allennlp-website/blob/master/drop.html) | 英文段落阅读，涉及计数、日期、比较、加减和多个答案片段 | 25 题：10 数值、10 单片段、5 日期/多片段 | 检查数字和组合推理；增加关系本身不能替代计算 |

这四组共 100 题、747 篇相关/干扰段落，是公开开发集的小样本。此次把各题的段落合成公共检索池，再测试抽取、检索和回答；不等同于四个数据集的官方榜单任务。语料来源、许可证和抽样历史见 [公共题库报告](public-qa-benchmark-report.md)。

它们不是用户 Downloads 文件夹的中文激素检测题库。前一轮用激素资料比较了建图；这一轮用公开英文数据诊断通用检索和 QA。后者不能证明中文检测项目、价格、采样条件、单位、参考区间等实际业务问答质量。

公共池也改变了原来的题目条件：“其父亲”等省略指代可能变得含糊，原先不可答的题可能从别处找到答案。公开数据是否进入模型训练无法确认，因此既不能把总分当作实际产品准确率，也不能用模型记忆命中标准答案代替证据支持。

## 分数变差有多大，有多少是评分问题

原比较的完整支持覆盖均为 **64/81（79.0%）**，没有任何一道题因新图而增加或丢失完整标准支持。精确匹配（EM）是规范化后与标准答案字符串匹配；F1 是词元重叠，不是人工语义正确率。

新图相对旧图：4 题从 EM 错变对，5 题从对变错，净差仅 1 题。探索性的精确配对检验 p=1.0；相对 fast 为 3 增、9 减，p≈0.146。这些小样本结果没有建立一般性优劣，检验也未处理共享文章依赖或公开数据污染。

旧图到新图的 5 个 EM 回退中，3 个是明显的答案表达/分段变化，例如：

- `The Ethiopian Empire` → `The Ethiopian Empire is older.`
- `Nicholas Barnewall` → 同时列出姓名与 `1st Viscount Barnewall`。
- `Russians` → 同时列出 `Russians` 和 `Russian forces`。

另两例为议会选举频率题改为拒答，以及把“首个商业化纺织装置”错答成水泵。后者源文实际讨论首个商业化蒸汽装置，属于真实的证据使用错误。

评分也会奖励无依据的猜中：`Cock and Bull` 作者出生年份题中，fast 回答 `1961` 得到 EM 分，但提供给模型的证据没有该出生年份；新图拒答反而失分。这并不是可靠问答质量的退步。语义复核模型同样会失误：它对 `counsel`/`council` 的拼写差异作过度严格解释，因此其结论不能当人工金标准。

## 控制实验：保留原文，只去掉图路径

对全部 100 题保留新图选出的原文、顺序、问题、回答提示、模型和预算，只把 `paths` 设为空。复用 88 个完全相同的历史请求；其余 12 个通过已授权的阿里 `qwen3.6-35b-a3b` API 新调用。没有重答挑优、修改标签或补充答案别名。

| 输入方式 | 完整标准支持 | EM | F1 |
| --- | ---: | ---: | ---: |
| fast：向量 + BM25 原文 | 64/81 | 42.0% | 53.8% |
| 旧图检索 + 路径 | 64/81 | 37.0% | 48.8% |
| 新图检索 + 路径 | 64/81 | 36.0% | 48.1% |
| **新图选出的相同原文，去掉路径** | **64/81** | **43.0%** | **53.4%** |

这是事后探索性消融，未重复采样估计生成波动。它支持“目前附加路径有净干扰”的解释，但不证明每个改答都是路径造成，也不能把 +7 个百分点当成真实语义准确率增益：其中有表达变化，也有恢复了无依据猜中的情况。没有路径时仍有 1 个历史协议错误，按原规则计零。

可核对的实际行为变化：

| 问题 | 带新图路径 | 同原文去掉路径 | 原文核查 |
| --- | --- | --- | --- |
| Mehmed V 赦免了几次阿尔巴尼亚起义的参与者？ | `1910`、`1911` | `2` | 源文有两次起义；应计数。附加路径却讨论阿尔巴尼亚语、马耳他语等使用地区 |
| 首个商业化纺织装置是什么？ | `water pump` | 拒答 | 原文仅支持蒸汽装置；路径讨论纺织博物馆所在地 |
| 某演员在 True Grit 中扮演谁？ | `Rooster Cogburn`、`U.S. Marshal` | 拒答 | 候选原文没有给出角色；路径只支持他出演另一部电影 |

也有反例：Miami Dolphins 球员昵称题，带路径答对、去掉路径拒答。因此应筛选有用路径，而不能从本次结果推出所有图上下文都应移除。

## 已定位的实现问题

### 1. 开放了语义词表，但输出协议可靠性下降

旧/新分别有 10/754、109/754 个窗口失败。逐条重新验证原始 JSON 后，新图 109 个失败文档中 **106 个涉及 qualifier 结构错误**：63 个文档出现缺失 `qualifiers`，46 个出现不支持的 qualifier 名称；两组有重叠。数量按文档计，未把多次调用当独立文档。

代码仍只允许 qualifier 名称 `condition`、`time`、`location`；模型生成了 `value`、`distance`、`score` 等字段。这里不是证据不存在，而是模型输出与服务协议不兼容。`json_object` 只约束 JSON 语法，不保证满足服务 schema。

两个值得修复的具体边界：

- [compact.py](../src/domain_kg/providers/compact.py#L126) 的完整格式示例只在 closed schema 下发送；开放类型时连同旧词表一起删除了示例。**这是失败增多的合理候选机制，尚未做单变量抽取实验，不能认定为已证实的唯一原因。**
- [extraction.py](../src/domain_kg/providers/extraction.py#L208) 只对证据校验错误作一次纠正；schema 错误转成 provider unavailable，不走同一纠正路径。错误有记录，但一次字段错误足以使整个窗口失败。

通过 JSON 校验也不意味着关系被保住。Warsaw City Council 例子中，首次响应列出 `Council members → every four years`，却没有把两个端点都放入实体表；纠正响应仍有未声明端点，最终有效图为空。原文包含明确的“四年一次”，说明“先想关系”仍需配套端点完整性检查。

这不是放松引用/权限校验的理由，也不能为了过检删掉时间、条件或单位。修复应明确结构协议、提供不限制词表的格式示例，并保留有界、可审计的纠正和原证据校验。

本基准让所有组仍可检索相同全文，所以 graph extraction 失败未使文本消失；真实材料发布仍要求完整成功。因此 14.5% 是实际构建可靠性问题，但**不能单独用来解释这次 QA 分数下降**，更不能把基准当失败材料可以部分发布的证明。

### 2. 重要证据已被召回，却未进入最终上下文

17 道未获得完整支持的问题共缺 23 个“问题—支持文档”项（不是 23 个去重文档）。其中：

- **20/23** 已在向量或 BM25 的前 50 候选里。
- 新图也找到了其中 **12/23**，但最终仍未选入。
- **6/23** 对应新图抽取失败；7/23 没有可用图节点。这些计数可重叠。

[fuse_evidence](../src/domain_kg/retrieval/fusion.py#L79) 有意避免同一文本得到重复投票：候选已存在于向量/关键词池时，即使图再次命中，也保持原来的文本排名。这能防止相关信号被重复计权，却也意味着发现关键中间证据未必能把它提入最终 12 段。

具体例子：Will Self 的介绍文档在向量第 **28**、新图第 **13**，含有出生日期，却仍未进入上下文。新图确实比旧图多发现了一份有用文档，但后续选择没利用这项收益。

离线反证：直接改用现成三路等权 RRF（不改图、不使用答案挑选）使完整支持从 **64/81 降到 58/81**，1 题改善、7 题退步。因此不能简单增加图权重或保留固定图名额；需要按问题所缺关系选择中间证据，评估整条链能否回答问题。

### 3. 图有两步路径，回答输入却只留下单步关系

新图选中原文所附的候选路径中共有 3,788 条单步、550 条两步路径；最终 100 个回答请求中的 **191 条路径全部是单步**。旧图 161 条中也仅 1 条两步。这是两组共享的问答呈现瓶颈，不能全部归因于新抽取算法。

原因可沿调用链核查：

- 许多向量命中文档的节点同时成为种子，最短路径容易从中间节点起算。
- 候选文档按相关性排序，但文档内部的多条路径未按问题所需关系重新排序。
- [path_context](../eval/scoped_retrieval.py#L258) 和 [qualified_paths](../eval/source_role_evidence.py#L176) 用 2,000 字符限制路径；每条边重复携带整段 quote。多步路径更长，每一步的证据还必须已被选中，容易被剔除。

这里的 2,000 字符打包来自 **评测回答适配器**，不是生产服务所有调用端都必须遵守的限制；生产候选融合和最短路径计算则被本次评测复用。不能把回答适配器的缺陷泛化成所有生产消费者的行为。

先前模型辅助审查中，新图有路径且判断有效的 77 题里，55 题被判“有原文依据但与问题无关”，22 题相关；另有 14 题审查失败、9 题没有路径。这只作辅助证据，逐例原文和消融实验更可靠。

生产 `SubgraphRequest` 的跳数上限为 2；尝试 4 跳的离线控制被类型校验拒绝，因此没有该控制结果，也未绕过校验。多跳数据题目并非必然对应相同数量图边，但目前策略明显缺少逐步补证据的能力。

### 4. 词表开放后，没有把同义关系变成可检索的一致语义

新图 1,958 个字面谓词中，1,321 个只出现一次。例如 `located in`、`is located in`、`located_in` 分别出现 157、138、19 次。这反映标签表达差异，不意味着同等数量的新关系含义。

[rank_graph_candidates](../src/domain_kg/retrieval/ranking.py#L175) 使用原文 BM25 和谓词词面线索；少量同义提示仍以 `located_in` 等固定字符串为键。开放标签可以进入图，但并没有自动获得语义相似度或同义归一能力。

修复方向应保留来源中的关系含义和标签，增加可审计的同义匹配/规范化，并保留方向、否定、时间和条件，而不是重新把所有关系硬塞进六个类型。

### 5. 删除孤立节点不是已证实的主要原因

把旧图只做孤立 observation 删除，保留原来的关系和检索算法，完整标准支持仍为 **64/81**。93/100 题最终原文完全不变，7 题发生候选变化，但支持覆盖没有变化。本控制只评估检索，没有另跑该变体的生成答案，不能据此声称所有影响为零。

同时，激素资料前一轮的“边数 +23.6%”也不等同于召回提高：增量集中在已存在的汇总文档，原始文档关系观察从 189 降为 171；共同成功窗口从 355 降为 329。没有人工关系金标准，不能把数量下降直接当作召回下降，但它说明之前的结构指标不足以宣称质量优化完成。

## 修复和后续验收的顺序

1. **先恢复抽取可靠性。** 分别测语法、端点完整性、原文支持、限定条件和有效非空图；保留开放节点/关系词表及失败可见性，不能以丢弃限定条件换成功率。
2. **再优化缺失证据的选择。** 使用问题中的实体与所需关系组织候选链；保留中间证据，验证它能进入最终上下文。仅加深遍历或增加图权重不是已有证据支持的修复。
3. **只呈现相关、完整的路径。** 区分用于召回的路径和用于回答解释的路径，按问题排序；引用可去重但不得丢失出处和限定条件。无增量信息时返回原文即可。
4. **用领域题验收，再扩公开样本。** 围绕用户的激素资料预先固定问题、标准答案、最小充分证据、单位/条件和不可答项，覆盖单表查找、跨文件比较、价格计算、采样要求和矛盾版本。报告支持证据是否充分、回答是否有依据及拒答是否恰当；EM/F1 保留为辅助指标。题目不能依据算法答案反向挑选。

本轮已经足够定位下一步，不继续对这 100 题调参选优。优化后的结论需要未用于诊断的样本及中文领域测试来确认。

## 可复现记录与本轮验证

全部新增脚本和原始公开数据调用保存在 Git 忽略目录 `.cache/connected-qa-2026-11-01/diagnosis/`：

- `diagnose.py`：原生产检索核心重放、原始 JSON 重新验证、旧图仅删孤立 observation 控制。
- `retrieval_controls.py`：路径打包追踪、三路 RRF 控制。
- `ablation.py`、`no-path-protocol.json`：全部 100 题去路径实验，模型调用前固定具体请求。
- `no-path-results.json`、`no-path-summary.json`：完整分母、原始错误和用量。
- `baseline-wire.json`、`revised-wire.json`、`*-retrieval.json`：逐文档/逐题诊断。

旧/新两组共 200 个原始检索输入输出重放与已保存 evidence 完全一致。新增 12 次阿里响应全部完成并返回用量：31,378 输入、725 输出 token；88 次结果复用不重复计调用。没有未知用量，不推算账单。

此次验证针对诊断与实验可复现性，不声称重跑了完整产品测试；前轮 15 项评测测试结果保持其原有范围。数据/源码冻结哈希、新消融的输入不变量和报告工件的校验另存 `verification.json`。
